## 1. Purpose & entry points

Two-way sync between an 8-sheet Excel workbook and a Simulink data dictionary (`.sldd`):

```
Excel -> validateDataDictionary -> Excel2Workspace (.m text) -> evalin('base') -> doWriteToSldd (Simulink.data.dictionary)
Excel <- sldd_to_excel (temp JSON) <- sldd_to_excel_helper.py (openpyxl) <- .sldd
```

* **GUI entry**: `sldd_gui.m:1` `function sldd_gui()` — the only App main file; declared as `fileset.main` in `AutoCreateSldd.prj:37-39`. Launch = type `sldd_gui` (`README.md:35-39`).
* **Programmatic entries** (documented `README.md:95-99`, all usable headless):
  * `Excel2Workspace(AllSheets, fullpath, outputFilename, filename, selection)` — `Excel2Workspace.m:1`; 0-arg mode prompts with `uigetfile` (:12-26); 4-arg mode opens `listdlg` (:41-51); 5-arg mode skips all dialogs (:38-40, :52-54) — this is the seam the GUI uses.
  * `[isValid, issues] = validateDataDictionary(fullpath, selectedSheets)` — `validateDataDictionary.m:1`, prints only when `nargout==0` (:68-70).
  * `sldd_to_excel(cleanExcel)` — `sldd_to_excel.m:1`, still opens `uigetfile` for the `.sldd` (:21-22).
* **Packaging**: MATLAB `deployment-project plugin="plugin.apptool"` (`AutoCreateSldd.prj:1`), `target="target.mlapps"` / `target-name="打包为 App"` (:2), app name `AutoCreateSldd`, version 1.0 (:16), GUID `ea502ba7-…` (:22), MATLAB root `E:\MATLAB\R2024b` (:60), platform `win64` only (:112-113).
  * `fileset.main` = sldd_gui.m; `fileset.depfun` = the 8 .m functions (:40-49); `fileset.resources` = the 2 .py scripts (:50-53). `+myPackage` is **not listed anywhere in the .prj** — it is picked up only because it sits in the app root and is added to the path by the app installer / user.
  * Build output `AutoCreateSldd.mlappinstall` (58,739 bytes) is committed though `.gitignore:140` says to ignore it.

## 4. Core algorithms / workflows

### 4.1 Load workbook (GUI)
`loadWorkbook` (:214-231) -> `refreshDerivedPaths` (auto-fills `<base>_objects.m` and `<base>.sldd` if empty, :916-929) -> `loadSheetsFromExcel` (:753-764) uses `cellstr(sheetnames(excelPath))`, selects `app.knownSheets = {'Signal','Parameter','Bus','BusElement'}` (:12), then previews the first selected sheet. At startup `tryLoadDefaultWorkbook` (:766-780) silently loads the **first `*.xlsx` in pwd**.

### 4.2 Template generation (`onGenerateTemplate` :267-357)
`uiputfile` (.xlsx, default `MCU_Template.xlsx` next to the current workbook, :268-278) -> `questdlg` 空模板 vs 含示例数据 (:281-284) -> build candidate script paths `{'generate_template.py', fullfile(pwd,...), fullfile(fileparts(mfilename('fullpath')),...)}` (:287-295) -> if `template_config.json` exists append ` --config "<cfg>"` (:298-302) -> `getPythonExe`; if empty, `questdlg` offers 打开设置… / 用 MATLAB 生成基本模板 / 取消 (:305-319) -> run:

```matlab
[ok,~] = system(sprintf('"%s" "%s"%s --empty "%s"', pyExe, scriptPath, cfgArgs, fullOutPath));   % :326
[ok,~] = system(sprintf('"%s" "%s"%s "%s"',        pyExe, scriptPath, cfgArgs, fullOutPath));   % :328
```

On success the new workbook is loaded into the GUI (:337-345). If Python is missing/unusable it falls back to `generateTemplateMatlab` (:1061-1113), which writes the 8 sheets with `writecell(...,'Sheet',...)` — a header-plus-one-example-row "basic" template that has **no data validation and no dropdowns** and hard-codes the Config candidate values from `loadTemplateConfigData`/`defaultTemplateConfig` (:1115-1164).

### 4.3 Validation (`onValidate` :458-481 -> `validateDataDictionary`)
Per selected sheet: `detectImportOptions(...,'Sheet',sn)` + all columns to `string` (:74-84) -> required columns (:26-31, matched case/space-insensitively :295-328) -> non-empty required cells (:87-103) -> then 4 cross-sheet passes: duplicate variable names across Signal+Parameter (case-insensitive, reports sheet 第 N 行, :106-144), duplicate Bus names (:147-175), BusElement->Bus existence (and "BusElement selected without Bus" error, :178-215), `DataType = "Bus: X"` existence via regex `^\s*bus\s*:\s*(.+?)\s*$` (:219-292). Returns a cellstr of issues; `isValid = isempty(issues)` (:66).

### 4.4 Excel -> .m objects (`doGenerateObjects` :573-611 -> `Excel2Workspace`)
Optional validation gated by `validateBeforeRunChk` (:580-589), append `.m` if missing, `mkdir` the folder, then

```matlab
Excel2Workspace(allSheets, excelPath, outputPath, [xlsxBase,'.xlsx'], selectedIndices);   % :605
```

Inside: read every selected sheet once into `sheetCache` (:74-93), process **Bus first** (:96-105) so element assignment has a target, then dispatch by exact sheet name (:120-141); unknown sheets are skipped with a message (:139-140); `Enum` writes separate class files into `outDir` (:137). Generated line templates (all via `fprintf(fid,...)`, UTF-8 via `fopen(...,'w','n','UTF-8')` :60):

```matlab
name = <Package>.Signal;                 % :276   (Parameter :324, Const :387)
name.CoderInfo.StorageClass = 'Custom';  % :229   (non-default SC only)
name.CoderInfo.CustomStorageClass = '<sc>';
try name.CoderInfo.CustomAttributes.HeaderFile = '<v>'; catch, end   % :285/:291 (Signal/Parameter only)
name.DataType = '<v>'; name.InitialValue = ...; name.Min/Max = <num>;
name.Description = '<v>'; name.DocUnits = '<v>'; name.Dimensions = <expr>; name.Complexity = '<v>';
% Parameter: Dimensions is written BEFORE .Value, "Simulink 要求设维度时 Value 为空" (:344-345)
% Const: <pkg>.Parameter; SC defaults to 'Define' (:389-395); .Value then .DataType, HeaderFile via CustomAttributes
BusName = Simulink.Bus; .Description .HeaderFile .Alignment .PreserveElementDimensions(true/false) .DataScope
saveVarsTmp{1} = Simulink.BusElement; ... saveVarsTmp{1}(n,1) = Simulink.BusElement; <Bus>.Elements = saveVarsTmp{1};
classdef <EnumName> < <DataType>  /  enumeration  /  <EnumNumbers> (<Value>)
```

Value formatting `fmtVal` (:185-208): `NONE`/empty -> `[]`; numeric strings pass through; `[...]` passes through; `TRUE/FALSE` -> `true/false`; anything else becomes a single-quoted string with doubled quotes. Default storage classes (`writeSC` :223-232): `Auto, SimulinkGlobal, ExportedGlobal, ImportedExtern, ImportedExternPointer` -> `.CoderInfo.StorageClass = '<v>'`; everything else -> `'Custom'` + `CustomStorageClass`.

### 4.5 Execute + write into .sldd (`onFullImport` :522-554 -> `doWriteToSldd` :613-747)
1. generate (4.4); 2. `scriptContent = fileread(outputPath); evalin('base', scriptContent)` (:529-530) — executed in the **base workspace**; 3. confirm dialog; 4. write:
* Collect candidates: `evalin('base','who')`, drop `ans` (:620-622), then either filter `isa(v,'Simulink.Signal'|'Simulink.Parameter'|'Simulink.Bus')` or intersect with `generatedInfo.Name`; values cached in a `containers.Map` to avoid a second `evalin` (:624-653).
* Open or create: `Simulink.data.dictionary.open(slddPath)` / `Simulink.data.dictionary.create(slddPath)` (:675-681), guarded by `onCleanup(@() safeCloseDict(dictObj))` (:682).
* `dataSect = getSection(dictObj,'Design Data')` (:684).
* Optional destructive pre-clean when `onlySaveGeneratedChk` is on: `cleanManagedEntries` finds local entries (`DataSource == '<name>.sldd'`) not in the keep list and `deleteEntry(dataSect,en)` for Simulink Signal/Parameter/Bus values only (:687-691, :1166-1183).
* Pre-fetch local entries once: `allExisting = find(dataSect)`, mask `strcmp({allExisting.DataSource}, slddRefName)` into a `containers.Map` keyed by `Name` (:694-707).
* Per variable: existing -> `getValue`, compare `isequal(struct(a),struct(b))` (:1056-1059); equal = skip, else `setValue`; missing -> `addEntry(dataSect,vn,newVal)`; per-item `try/catch` counts failures (:709-732).
* `saveChanges(dictObj)` (:734), log `+added ~updated -skipped xfailed` (:735), then reopen and count entries as verification (:737-746).
* APIs actually used: `Simulink.data.dictionary.open/create/close`, `getSection`, `find`, `addEntry`, `deleteEntry`, `getValue`, `setValue`, `saveChanges`. **No** `importFromFile`, `exportToFile`, `set_param`, `new_system`, `add_block`, `coder.mapping.*` or `sltest` anywhere in this app (verified by grep).

### 4.6 Reverse sync (`onReverseSync` :504-520 -> `sldd_to_excel(cleanExcel)`)
`uigetfile` for `.sldd` (:21-22) -> `open` + `find(getSection(...,'Design Data'))` + local-only filter by `DataSource` -> `close` (:30-35) -> classify by class: `Simulink.Bus` (elements flattened as `{busName, BusElement}`), `Simulink.Parameter` -> `Const` iff `CoderInfo.CustomStorageClass == 'Define'` else `Parameter`, `Simulink.Signal` (:39-60) -> per-sheet rows via `getSignalRow/getParamRow/getConstRow/getBusRow/getBusElemRow`, numbers/logicals stringified (:97-116), `requiredCols` attached (:256-264) -> JSON `{excelPath, cleanExcel, sheets.{Signal,Parameter,Const,Bus,BusElement,Enum}}` -> `jsonencode` to `fullfile(tempdir,'sldd_to_excel_temp.json')` (:187-190) -> `getPythonExe` (hard error if unset, :193-198) -> if the target .xlsx does not exist, run `generate_template.py --empty` first (:203-217) -> `system('"<py>" "<sldd_to_excel_helper.py>" "<json>"')` (:219-226) -> delete temp JSON (:228).
Enum rows are recovered by scanning **every `*.m` in the .sldd folder** for `classdef X < Base` and `^\s+(\w+)\s*\(([^)]+)\)\s*$` lines, skipping `*_objects.m`, `sldd_to_excel.m`, `sldd_to_excel_helper.m` (:131-179).

Python merge semantics (`sldd_to_excel_helper.py`): load workbook -> for each sheet in JSON, if `clean` **or** sheet in `('Enum','BusElement','Const')` -> `ws.delete_rows(2, max_row-1)` then append all rows; else build a name->row map from column 1 and overwrite matched rows / append new ones (:57-103). Cell typing: bool passthrough, `'true'/'false'` -> bool, numeric-looking -> int/float, else str (:87-101); empty SLDD values leave the existing Excel cell untouched (:103).

## 5. Data formats & schemas

### 5.1 The 8-sheet Excel contract (sheet name = data category)
Authoritative column order = `generate_template.py:244-404` and `sldd_to_excel.m:237-253` (identical); required-vs-optional colouring = the fill arrays in `generate_template.py` (dark blue `FF1F4E78` = required, light blue `FFD9E2F3` = optional, sample rows `FFE2F0D9`):

| Sheet | Columns (A->) | Required (template fill / validate / reverse-sync) |
|---|---|---|
| History | Version, ChangeDate, Changer, Content | none (blue `5B9BD5` header only) |
| Signal | VariableName, Package, Object, CustomStorageClass, DataType, InitialValue, HeaderFile, DefinitionFile, Description, Min, Max, Unit, Dimensions, Complexity | A-E, per `validateDataDictionary.m:27`; reverse-sync `[1 2 3 4 5 7 8]` (`sldd_to_excel.m:258`) |
| Parameter | same 14 | A-F (:28; reverse `[1 2 3 4 5 6 7 8]` :259) |
| Const | Name, Package, CustomStorageClass, Value, DataType, HeaderFile | A-C (`generate_template.py:333`); **not validated at all** |
| Enum | EnumName, EnumNumbers, Value, DataType | all 4 (`generate_template.py:347`); **not validated**; reverse `[1 2 3 4]` |
| Bus | BusName, Description, HeaderFile, Alignment, PreserveElementDimensions, DataScope | A,C,D,E,F (`generate_template.py:367`, :29); reverse `[1 3 4 5 6]` |
| BusElement | BusName, ElementName, DataType, Dimensions, Description, Unit | A-D (:30); reverse `[1 2 3 4]` |
| Config | Package, Object, Storage class, Data Type, Unit, DimensionsMode, Complexity, DataScope | data source for the dropdowns; not imported |

* Header cells are written in **row 1**, data from row 2; `generate_template.py` freezes row 1 (`freeze(ws,'A2')`) and applies 宋体 11pt + centred alignment.
* Dropdowns: `DataValidation(type='list', formula1='Config!$X$2:$X$n+1')` over rows 2..`MAX_ROWS=500` (:152, :179-191); Signal/Parameter bind B(Package), C(Object via `obj_ref` single-cell), D(StorageClass), E(DataType), L(Unit), N(Complexity); Const binds B, C, E; Enum binds D; Bus binds F(DataScope); BusElement binds A -> `Bus!$A$2:$A$1000`, C -> DataType, F -> Unit (:281-286, 309-314, 335-337, 350, 370, 390-392).
* Cross-sheet references used by the contract: `Config` is the enumeration source; `Bus` sheet is the BusElement parent source; `DataType` values may be `Bus: <BusName>`.

```json
 "DimensionsMode":["Fixed","Variable"],"Complexity":["real","complex"],
 "DataScope":["Auto","Exported","Imported"]}
```

Keys are the canonical names; the file maps them to Config column letters A-H and to display headers `Package, Object, Storage class, Data Type, Unit, DimensionsMode, Complexity, DataScope` (`generate_template.py:59-80`, `sldd_template_config.m:15-29`, `sldd_gui.m:1151-1164` — three copies that must stay in sync). Empty list `[]` = clear that column (no values, no dropdown). Readers: `generate_template.py:84-124` (list-or-scalar tolerated, blanks dropped), `sldd_template_config.m:313-349`, `sldd_gui.m:1115-1149`. Written compact single-line by `jsonencode` (`sldd_template_config.m:387-401`).

### 5.3 `python_config.json`

```json
{"PythonPath":"D:\\SoftwareInstallation\\Python3147\\python.exe"}
```

Single field, written by `sldd_python_config.m:222-243` (empty path => file is **deleted**), read by `getPythonExe.m:44-73`. Accepted user input: full `python.exe`, install directory (scans `python.exe|python3.exe|python3|python`), or bare command name (`check_python_exe.m:76-114`); quotes stripped (:68-74); embedded quotes/newlines rejected (:33-36).

### 5.4 Generated .m object script
Header: `%%%% 自动生成的数据对象文件` + creation time + source Excel (`Excel2Workspace.m:65-69`); sections marked `%%%% ================ <Name> 对象 ================` (`writeSec` :210-213); per object a comment `%%%% ----- Signal: <name> -----` then one assignment per line, ending with a blank line. Enum class files are `<outDir>/<EnumName>.m`, format `classdef X < uint8` + `enumeration` block (:545-553). Scripts are UTF-8 with `%%` comments only, so `evalin('base', fileread(...))` is legal.

### 5.5 Reverse-sync JSON (temp file, schema not versioned)

```json
{"excelPath":"...","cleanExcel":false,
 "sheets":{"Signal":{"headers":["VariableName","Package","Object"],
                    "requiredCols":[1,2,3,4,5,7,8],
                    "rows":[["M_Sig","myPackage","Signal"]]}}}
```

`rows` is an array of arrays aligned to `headers`; column 1 is the identity key for incremental matching.

### 5.6 Name-validation rules
There are **no identifier rules**. The only checks are: required cells non-empty, duplicate `VariableName` across Signal+Parameter (case-insensitive, `validateDataDictionary.m:106-144`), duplicate `BusName` (:147-175), and Bus reference existence. Nothing rejects spaces, leading digits, MATLAB keywords, package names that are not on the path, storage classes that do not exist, or `DataType` strings that are not real types — those fail later as MATLAB syntax/runtime errors inside the generated script.

## 6. External dependencies & environment assumptions

* **MATLAB R2024b** required per README (`README.md:20`) and .prj (:60), but `csc_registration.m:16-17` was generated by **R2022b Update 10** (`MATLAB version: 9.13.0.2698988`) — version skew in a shipped artifact.
* **Simulink** is mandatory (only `Simulink.data.dictionary.*`, `Simulink.Signal/Parameter/Bus`, `Simulink.BusElement`, `Simulink.CSCDefn` are used). .prj additionally declares `matlabcoder, embeddedcoder, gpucoder, fixedpoint, matlabhdlcoder, neuralnetwork` toolboxes (`AutoCreateSldd.prj:61-98`) — inherited boilerplate from the App-packaging template; only fixed-point/embedded-coder concepts are relevant to storage classes and are not called by this code.
* **Python 3 + openpyxl** (`README.md:21-22`); `generate_template.py` also needs **tkinter** when no output path is supplied (:40-52) — common Windows Store Python installs lack it. Python is used only for (a) template generation, (b) reverse-sync Excel writes, (c) auto-creating the workbook during reverse sync.
* **No Python auto-discovery** by design (`getPythonExe.m:10`): pyenv/PATH/registry are never consulted, so first-run "生成模板" -> prompt -> settings dialog.
* **Config file location** = next to `mfilename('fullpath')` (`python_config_path.m:10-19`, `sldd_gui.m:405-413`), i.e. inside the installed app folder after `.mlappinstall` — writing there can fail for per-machine installs under Program Files; there is no `prefdir` fallback.
* **Path requirement**: the folder containing `+myPackage` must be on the MATLAB path for `myPackage.Signal`/`myPackage.Parameter` and the 16 CSCs (`README.md:126-130`); the .prj does not package it explicitly.
* **Hard-coded names/paths**: `MCU_Template.xlsx` (`sldd_gui.m:270,273`), `MCU_Template_objects.m` (:238), `MCU_Template.sldd` (:255), `'Design Data'` section (:684,740; `sldd_to_excel.m:31`), `sldd_to_excel_temp.json` (`sldd_to_excel.m:187`), the two .py filenames, class-name strings in `isa` checks, and the `.sldd` DataSource suffix comparison (`sldd_gui.m:698`, `sldd_to_excel.m:33`).
* **Windows-specific**: .prj platform block `win64/win2k/osver 10.0` (:100-114); `system()` commands built with double quotes; `ispc` branch that appends `.exe` (`check_python_exe.m:102`); backslash paths; Chinese UI strings/localised fonts; `%TEMP%` via `tempdir`.
* **Excel**: relies on `sheetnames`, `detectImportOptions`, `readtable`, `writecell`, `xlsfinfo` (`Excel2Workspace.m:21`), so an Excel-compatible reader must exist; `.xls` is advertised in the picker but the generated script name always assumes `.xlsx` (`sldd_gui.m:603-605`).

## 7. Known constraints, bugs, gaps

1. **Enum objects never reach the .sldd.** `Excel2Workspace` writes `<EnumName>.m` classdefs (:137, 515-557) but `onFullImport` only `evalin`s the objects script (`sldd_gui.m:528-531`); classdefs cannot be `evalin`'d into base and are not in `generatedInfo`, so `doWriteToSldd` never sees them.
2. **Package<->StorageClass mismatch aborts the whole script.** `writeSC` emits `.CoderInfo.CustomStorageClass = 'YS_SelectRAMSignal'` unconditionally (`Excel2Workspace.m:223-232`); if the row says `Package=Simulink` (the `orDef` default, :273/:321) that assignment errors and, unlike HeaderFile/DefinitionFile (:285/:291 use `try ... catch, end`), it is **not** guarded — `evalin` then aborts mid-import. Validation does not check the Package/StorageClass pairing.
3. **Const vs Parameter is inferred from one storage class only** in reverse sync (`sldd_to_excel.m:50-56`): only `Define` maps back to the Const sheet; `Const`, `Volatile`, `ConstVolatile`, `ImportedDefine`, `CompilerFlag` rows become Parameter rows. Forward direction can put those classes in Const, so a round-trip loses the sheet assignment.
4. **Reverse sync ignores the GUI's 数据字典 path.** `onReverseSync` just calls `sldd_to_excel(cleanExcel)` (`sldd_gui.m:513`), which always `uigetfile`s (:21-22). The `slddPathEdit` field is only used by the forward path.
5. **Inconsistent required-column sets.** `sldd_to_excel.m:258` marks Signal HeaderFile/DefinitionFile as required; `validateDataDictionary.m:27` and the README say the first 5. `requiredCols` is shipped to Python but never used there (`sldd_to_excel_helper.py:44` only defaults it).
6. **Validation covers only 4 sheets.** `requiredColumns` has no Const/Enum entry and `selectedSheets` is intersected with those field names (`validateDataDictionary.m:26-34`), so **Const and Enum are silently never validated** even when selected in the GUI.
7. **Reverse-sync Enum discovery is folder-wide.** It parses every `*.m` beside the .sldd (`sldd_to_excel.m:131-158`) except three hard-coded names — any unrelated classdef in that folder is misread as an enum.
8. **`onlySaveGenerated` is dead logic.** Both branches compute `varNames = {generatedInfo.Name}` and differ only in a log string (`sldd_gui.m:538-544`); destructive cleaning is actually controlled by `shouldClean`, and it deletes **all** local Simulink object entries not in the keep list — not just previously generated ones (:1166-1183).
9. **Confirm-cancel is not honoured.** Cancelling the write confirm `return`s from `doWriteToSldd` (:668-670), but `onFullImport` still logs `[3/3]` and sets status "导入完成" (:546-549).
10. **Silent generation failures.** `readSheet` catches read errors and returns an empty table with only a `warning` (`Excel2Workspace.m:154-166`); the GUI can therefore report "objects 已生成" for an empty script, and `doWriteToSldd` then errors with "没有可写入的变量" (`sldd_gui.m:655-657`).
11. **Dictionary lifecycle**: no lock/conflict handling; `open`/`create` are outside the per-item `try` (:675-681), and verify re-opens a second handle (:739-746). `sldd_to_excel.m` opens read-only and closes without `onCleanup` (:30-35), leaking a handle if classification throws.
12. **Header-name brittleness.** `Excel2Workspace` accesses fields by literal name (`r.VariableName`, `r.CustomStorageClass`, ...) after `detectImportOptions` with the default naming rule (:154-160), while the GUI preview uses `opts.VariableNamingRule='preserve'` (`sldd_gui.m:969-980`) and validation tolerates spaces/case (`validateDataDictionary.m:307-328`). A header like `Data Type` previews fine but silently drops the property at generation time (all property writes are guarded by `any(strcmpi(col,field))`, `Excel2Workspace.m:234-257`).
13. **Dead/legacy code**: `onClearIssues` (`sldd_gui.m:565`), `toCmp` (`sldd_to_excel.m:333`), `defaultSelection(...,ensureMin)` where `ensureMin` is never passed (`sldd_gui.m:958-962`), `filterExportedObjectInfo`'s `BusElement`/`*_elements` filter that the current generator can never produce (:1046-1054; BusElement is written straight into `<Bus>.Elements`), and `Tag` values that nothing queries.
14. **Log growth**: `appendLog` appends indefinitely to the edit control's `String` with `drawnow` each call (:892-900); `'Max',200` only makes the control multi-line.
15. **Reverse sync requires Python unconditionally** and dies via `error(...)` if unset (`sldd_to_excel.m:193-198`) — there is no MATLAB-side Excel writer for reverse sync, although there is for template generation.
16. **`csc_registration.m` oddities**: generated for package `myPackage` (16 CSC + 5 memory sections, :23-631, 633-704), memory-section pragmas misspelled `// #pragram section ...` (:641-642, 655-656), `YS_RAMPara` marked `IsConst=true, IsVolatile=true` (:659-660), and `MemConst*` entries carry only human comments. Hand-editing is discouraged by the generator banner (:7-15).
17. **Repo hygiene / rename residue**: `.gitignore` still lists `DictSync.mlappinstall`, `DictSync.prj`, `sldd_gui.prj`, `sldd_gui.mlappinstall`, `MCU_Template_objects.m`, `*.xlsx`, `*.sldd` (:120-150), i.e. earlier names for this same tool; the built `.mlappinstall` is committed despite being ignored.
18. **Missing referenced items**: `sldd_to_excel.m:137-139` skips a `sldd_to_excel_helper.m` that does not exist; no `+myPackage` entry in the .prj; no tests, no CI, no LICENSE.

## 8. Merge assessment (into the single-window all-in-one app)

**Reusable as-is (service layer, no UI):**
* `validateDataDictionary(fullpath, selectedSheets)` -> `(isValid, issues)`: pure function, cellstr reporting, only the `nargout==0` banner is UI-ish. Only change: add Const/Enum sheets to `requiredColumns` and add identifier/CSC/DataType checks.
* `Excel2Workspace` 5-arg form: file-in/file-out with no dialogs (`Excel2Workspace.m:38-54`). Recommended refactor to `scriptText = buildObjectsScript(sheets, path, selection)` returning text + a structured object list, so the merged app can preview/execute without a temp file.
* `doWriteToSldd` core (`sldd_gui.m:613-747`): the most valuable logic in the app (value cache, local-entry mask by `DataSource`, add/set/skip counting, `saveChanges`, verification). Extract verbatim into `writeObjectsToDictionary(dictPath, varNames, opts)` with `opts.ConfirmFcn` replacing the `questdlg`, returning a stats struct.
* `check_python_exe`, `getPythonExe`, `python_config_path`: coherent seam, single source of truth; keep, but relocate config to `prefdir`/app-data with the current file as fallback.
* `generate_template.py` (argparse + `--empty`/`--config`/output), `sldd_to_excel_helper.py` (JSON->workbook merge), both JSON schemas: keep as packaged resources; they are already UI-free CLIs.
* `+myPackage/*`: ship untouched on the path. `csc_registration.m` is a generated MathWorks artifact; `@Signal`/`@Parameter` only add `setupCoderInfo` -> `useLocalCustomStorageClasses(h,'myPackage')` (`Signal.m:44-49`).

**UI-coupled — must be rewritten:**
* All 1189 lines of `sldd_gui.m` layout/callbacks: fixed 1380x820 non-resizable classic `figure`, absolute pixel child positions, normalised panel positions, nested-closure `app` struct, figure-level `uicontextmenu` for settings, `uigetfile/uiputfile/questdlg` modals, edit-box log + status text. A merged single-window app needs resize-aware layout, a document/workspace model instead of `setappdata('AllSheets')`, and one shared logger/status bar.
* `sldd_template_config.m` / `sldd_python_config.m`: business helpers (`loadCfgFile`, `cleanCfg`, `writeJsonFile`, `readJsonPath`, `writeJsonPath`, `refreshTable` logic) port over; the modal-figure shells, `uiwait`/`uiresume`/`Result` appdata protocol and `errordlg` construction guard do not.
* Ask/report patterns: replace `questdlg` chains (`sldd_gui.m:281, 310, 666`) with the merged app's dialog/prompt service; unify the three separate `setStatus` implementations.

**Behavioural invariants a merged app must preserve:**
1. The 8-sheet names, exact column order, required/optional colouring and Config-driven dropdowns (users have existing workbooks).
2. Generated .m text semantics: `<name> = <pkg>.Signal|Parameter;` + `CoderInfo` + property lines, BusElement via `saveVarsTmp{1}`, Enum classdef layout — so existing generated scripts and diffs stay meaningful.
3. Forward pipeline order and gates: optional pre-validation -> generate -> execute in base workspace -> optional confirm -> write; the four checkboxes keep their meanings and defaults (validate=on, confirm=on, both destructive flags off).
4. Incremental-by-default reverse sync; clean mode opt-in; Enum/BusElement/Const always whole-table rewritten; column-1 name key for Signal/Parameter/Bus; `History`/`Config` never touched.
5. Partial-failure tolerance and the `+added ~updated -skipped xfailed` summary; per-object failures must not abort the batch.
6. Python stays optional for template generation (MATLAB basic-template fallback) and mandatory only for reverse sync.
7. File/naming conventions: `<workbook>_objects.m`, `<workbook>.sldd`, `<EnumName>.m` next to the script, `template_config.json`/`python_config.json` per machine, temp JSON in `tempdir`.

**Merge hazards to design for:** the app mutates the MATLAB **base workspace** via `evalin('base', scriptContent)` (`sldd_gui.m:530`) and then reads `who`/`evalin` — a merged app that also creates Simulink models must scope this (dedicated workspace/temporary namespace, shadowing check, cleanup), otherwise model variables and dictionary variables collide. Likewise two tools writing the same `.sldd` need one owner of the `open/addEntry/saveChanges` lifecycle (`onCleanup`-guarded, single handle) to avoid stale entry maps.
